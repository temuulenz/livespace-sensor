# LiveSpace Sensor permanent requirements

- Kotlin and Android XML Views only; package com.livespace.sensor; preserve minSdk 23.
- Keep dependencies minimal. Verify runtime API and native ABI compatibility on the actual device (SM-N910U currently exposes armeabi-v7a, armeabi).
- Follow phased implementation and build after each phase. Stop at the end of each phase and report verified results; do not implement a later phase without authorization.
- Camera2 and YUV_420_888; process locally on a worker, throttle expensive work, and always close images and camera resources.
- No raw images, video, or audio saved or transmitted. No facial recognition, identities, or identity tracking.
- Person count means observed people, not total venue occupancy. Use null/unavailable for missing metrics. Never fabricate measurements or tests.
- Audio: AudioRecord, RMS and dBFS; SPL requires calibration. AI: verified 8-bit quantized SSD MobileNet V1 TFLite, CPU first; no forecasting training on device.
- Future networking: authenticated OkHttp WebSocket, WSS in production, normal certificate verification, explicitly enabled local development only; versioned JSON, UUID message IDs, ACKs, bounded SQLite queue and backoff.
- Never commit credentials. Validate external configuration. Inspect the real backend before choosing endpoints or authentication. Do not modify unrelated backend functionality.
- Background operation and screen-off reliability require a later Foreground Service phase and physical testing. Do not claim unrestricted 24/7 reliability.
- Preserve unrelated work; no destructive system actions or sudo without explicit approval. Ask before major changes to the agreed architecture.
- Keep architecture, protocol, device profile, testing evidence, limitations, and roadmap documented. Report compilation/runtime failures honestly.
- Phase 2 uses the canonical SSD MobileNet V1 quantized UINT8 model (not signed INT8 I/O), pinned TFLite 2.8.0 and ARMv7 packaging. TFLite 2.14.0 failed native loading on the Note 4; do not upgrade without repeating physical loading/operator checks. See docs/MODEL_PROFILE.md.
- Keep inference bounded to one in-flight buffer/invocation; never close an interpreter concurrently with inference. Preview and boxes must share the same upright full-field coordinate transform. Confidence summaries are not calibrated occupancy accuracy; the detector has a 10-output cap.
- Debug benchmarks may record structured timings/counts/memory/temperature only, never raw media. Keep incomplete runs separate; compare at least 30 successful samples where practical. Stop prolonged benchmarking at the chosen conservative battery-temperature limit (42 °C), or earlier on instability; never disable thermal protections.
- Phase 3 audio uses foreground-only AudioRecord mono PCM16 (prefer 16000 Hz), reusable transient buffers and a dedicated owner thread. Stop/Home must release microphone resources; microphone denial/failure must leave AI available. Never save/log/transmit PCM.
- RMS is normalized by 32768. dBFS has a finite −120 numeric floor, not physical SPL. Rolling average uses linear energy; rolling peak is the maximum absolute PCM sample. Manual SPL calibration is optional and off by default; floor/silence has no SPL estimate. Do not claim A-weighted/certified sound-meter accuracy.
- TelemetryRepository exposes an immutable synchronized snapshot with producer timestamps and stale-data nulls. No Phase 4 networking/queue/service work is authorized by Phase 3.
- Phase 4 and later must follow the frozen `docs/SENSOR_PROTOCOL.md` exactly; do not add envelope fields or application heartbeats without a protocol revision. Only `accepted`/`duplicate` ACKs acknowledge a message. Retry the same immutable JSON and ID. Phase 4 queue is bounded and volatile; durable SQLite outbox is Phase 6.
- OkHttp 4.12.0 is pinned after Android API 23 Note 4 verification. Keep `wss://` TLS/hostname verification enabled. Allow `ws://` only for explicitly opted-in private LAN development endpoints. Device tokens use API 23 AndroidKeyStore AES-GCM; never display/log/store a plaintext token.
- Use OkHttp's 30-second WebSocket control-frame ping interval; retain automatic pong responses for peer pings. Missing pong must flow through normal reconnect/backoff. Never add JSON heartbeat messages unless the authoritative sensor protocol explicitly requires them.
- TextureView preview applies the display correction once because TextureView handles sensor orientation; keep its upright fit-center rect shared with detection overlay, and retain sensor-minus-display rotation for YUV/model preprocessing. Unit/benchmark rotation coverage does not replace human visual confirmation.
- Continuous sensing is owned only by the explicit user-started foreground `SensorService`; never autostart camera/microphone at boot. Keep a persistent Stop action, hold a partial wake lock only while necessary, and release all owners on Stop. Activity/TextureView lifecycle must not own analysis resources.
- Phase 6 telemetry persistence is app-private SQLite and JSON-only. Default bound is 10,000 messages / 24 hours. ACK deletion requires the frozen protocol's accepted/duplicate status and the same configured device/location; no raw media is persisted. Expired, dropped and rejected data must be counted and surfaced, never silently discarded.
